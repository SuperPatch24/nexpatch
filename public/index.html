What it does

Everything between “a new version is out” and “every device has it.”

Four jobs most Intune teams do by hand, in one place.

Discover

See every app installed across your devices, how many versions are out there, and which ones can be patched.

Patch in rings

New versions go to a pilot group first, then wider rings, with install deadlines you set.

App Control, made simple

Build App Control policies with plain-language choices. Audit first, allow what people need, then enforce.

Prove it

Compliance trends, exposure and install results, ready for Excel or a weekly status email.

How it works

Up and running in three steps.

No servers to manage and nothing to install on devices.

  1. Connect your tenant

    Sign in with your Microsoft work account. An admin approves NexpatchOnline’s access once.

  2. Choose apps and rings

    Pick the apps to manage, who gets updates first, and how long each ring waits.

  3. Stay current

    NexpatchOnline checks for new versions, rolls them out ring by ring, and reports what happened.

Security

Your tenant stays in your control.

NexpatchOnline works through Microsoft Graph with permissions you review before you approve. You can see what it does, and remove it at any time.

  • No agentsUpdates install through the Intune Management Extension already on your devices.
  • Clear permissionsEvery Microsoft Graph permission is listed before you connect.
  • Revoke anytimeRemove NexpatchOnline’s access from Microsoft Entra ID whenever you choose.
  • Pilot firstEvery update reaches a small test group before anyone else.

    Import Microsoft Store apps in bulk

    Find Store product IDs with WinGet on a trusted Windows workstation. Include the app’s Package Family Name (PFN), obtained from a test device after installing the app.

    winget search --source msstore "app name"

    Paste a JSON array containing name, id, packageFamily, optional publisher and optional reg (installed display name).

    Versions shown are sample data until you import inventory. Store app IDs and PFNs must be verified before use. Store entries are catalog-only until native Intune Store publishing is implemented and validated; they cannot be published from NexpatchOnline yet.

    Deploy it with Intune

    1. Set the base policy ID on the Activity tab (the ID of the policy built on the Base policy tab).
    2. Download the policy XML after your latest allow decisions.
    3. Intune → Endpoint security → App Control for Business → Create policy → upload the XML, or replace the file in the existing NexpatchOnline supplemental policy, and assign it to the same devices as the base policy.

    Automatic deployment after each decision is coming next.
