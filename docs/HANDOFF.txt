1. WHAT THIS IS
---------------
NexpatchOnline is a multi-tenant SaaS platform for Microsoft Intune, similar to Patch My PC,
plus managed App Control for Business (WDAC). Client IT teams sign in with their Microsoft work
account, approve NexpatchOnline for their tenant, and then from the website:
  - see apps installed on their devices (inventory/discovery from Intune)
  - publish third-party app updates to Intune with full deployment options (one click, cloud-side)
  - build and deploy App Control base and supplemental policies, and review blocked/audited apps
  - manage which of their people can use the platform (roles)
The operator (owner of NexpatchOnline) has an admin area: shared app catalog, all client
organizations with usage, cross-client deployment logs, and trial/paid plan control.

Business model: 30-day free trial per organization, then paid. Suggested pricing (not final):
  Patch  $0.50/device/month (min $25/month), Secure (Patch + App Control) $1.00/device/month
  (min $50/month), volume discounts at 500+ devices, annual = 2 months free, CAD and USD.
  Competitor reference (third-party listing, verify): Patch My PC $2.00-$3.50/device/year with
  $1,499-$2,499/year minimums. Edge: low minimums for small businesses + App Control as a service.

4. HOW KEY FLOWS WORK
---------------------
Sign-in: MSAL.js redirect flow (fragment response), authority "organizations". When apiBaseUrl is
  set, login requests api://<clientId>/access_as_user. Sample/demo mode needs no sign-in.
Connect organization: admin consent via https://login.microsoftonline.com/{tenant}/v2.0/adminconsent
  -> returns to /consent -> site calls POST /api/tenant/activate -> backend tests Graph access,
  marks tenant active, first user becomes owner, starts 30-day trial, then syncs inventory.
Inventory: GET deviceManagement/detectedApps (Windows only) on connect, on demand, nightly 07:00 UTC.
Publish to Intune: website POSTs app + options to /api/publish -> job row + storage queue message
  -> publishWorker builds package (only a small PowerShell wrapper; winget installs on device),
  encrypts, uploads, sets relationships and assignments. Website closes dialog and polls job on
  Deployments page. Same version already in Intune => only assignments are added.
Device install wrapper (Install-Update.ps1): relaunches in 64-bit PowerShell if started 32-bit;
  finds winget under %ProgramW6432%\WindowsApps; if missing, installs App Installer for all users
  (Repair-WinGetPackageManager, fallback: provision aka.ms/getwinget msixbundle + dependencies);
  handles running apps (close/notify/wait/defer exit 1618); pre/post scripts (base64); uses
  --source winget --scope machine; logs to C:\ProgramData\NexpatchOnline\Logs\<wingetId>.log.
  Exit codes: 2 = winget unavailable (Intune shows 0x80070002), 1 = other error.
App Control:
  Event sources (client chooses): Microsoft Defender advanced hunting (needs E5/MDE P2) polled every
    15 min, OR Nexpatch collector (scheduled task deployed as Intune platform script, reads
    CodeIntegrity events 3076/3077/3089, posts to /api/appcontrol/ingest with per-tenant key).
  Decisions: allowPublisher / allowFile / block / ignore / undo.
  Base policy: built from Microsoft template, deployed via Graph configurationPolicies
    (template 4321b946-b76b-4450-8afd-769c08b16ffc_1, family endpointSecurityApplicationControl).
  Supplemental: built from allow decisions, deployed via Graph
    (template 08441ae9-e0c0-4e57-8e8b-6e72405cd64f_1, family
    endpointSecurityApplicationControlSupplementalPolicy). Same policy ID kept across updates.
Roles: viewer (read), admin (publish/sync/App Control), owner (also manage people).
Platform admin: shared catalog (Catalog table, partition "global"), organizations + usage,
  deployment logs across tenants, plan changes (activate/extend/restart/expire).
Trial: plan fields on Tenants row; publishing and sync return HTTP 402 when trial ended.

6. HOW TO DEPLOY CHANGES
------------------------
Normal path: commit/push to main (GitHub Desktop or github.com upload). Website -> Cloudflare.
  api/** changes -> GitHub Actions deploys the function app. Never overwrite public/config.js.
Manual fallback (Azure Cloud Shell, Bash):
  cd ~/nexpatchonline/api && npm install --omit=dev
  func azure functionapp publish nexpatch-api-20022 --javascript      (the --javascript flag is required)
  az functionapp restart -g nexpatch-rg -n nexpatch-api-20022
Health check: https://nexpatch-api-20022.azurewebsites.net/api/me -> 401 "Sign in required" is correct.
After changing device scripts: existing Intune apps keep the OLD script. Delete those app versions
  in Intune and publish again (same version present => only assignments are added).


7. LESSONS / GOTCHAS ALREADY SOLVED
-----------------------------------
- Some Graph actions (file commit, updateRelationships, assignments) return EMPTY bodies: parse text.
- Intune Available assignments reject useLocalTime and deadline: send only startDateTime (UTC).
- Restart grace settings only valid when app restart behavior = basedOnReturnCode.
- A freshly uploaded app may reject assignments briefly: retry once after 15 s.
- Win32 install commands can run in 32-bit PowerShell: relaunch via %windir%\sysnative, use
  %ProgramW6432%. Run winget from its own folder as SYSTEM. Use --source winget.
- IntuneWin32App PowerShell module param names were verified against its source (used for the
  PowerShell fallback). The cloud publisher mirrors the module's Graph request bodies.
- Flex Consumption: defaultHostName empty in CLI; func publish needs --javascript in Cloud Shell.
- GitHub OIDC subject includes owner/repo IDs (repo:Owner@id/repo@id:ref:...).
- Browser saves re-downloads as "name (1).zip" - verify file size before uploading.
- New domains get blocked by corporate web filters.
- Each signed-in organization gets an empty browser workspace; sample data only in demo mode.
